Julia API の実測対応表 ​

通常配列の呼び出しが成功するかと、その入口を Colmat が提供するかを分けて記録します。 入口は Julia 1.13 のラッパー実装から選び、LBT の登録先を照合します。動的な呼び出し回数の計測やライブラリ内部を追跡したトレースではありません。

検証条件 ​

  • Julia: 1.13.3 / x86_64-linux-gnu。

  • Colmat ソース: bc0dce2af48590dec20f99976ad7aee8b999a447。

  • Rust colmat ソース: e1c83482f5a61449d30e989808c3ba5f751ec391。

  • Julia の BLAS 整数 ABI: ilp64。

  • Colmat 実行幅: 1。

  • 要素型は Float32 / Float64 / ComplexF32 / ComplexF64 の順。

判定の範囲 ​

  • 「成功」は、このプローブの小さな有限値入力で参照計算または分解の残差を満たしたことを表します。

  • 行列積・求解・分解再構成の残差は、BLAS を呼ばないスカラーの積和で確認します。

  • 「既存バックエンド」での成功は、Rust colmat の該当分解が接続済みであるという意味ではありません。

  • Rust 側の機能名は固定 revision の faer/src/linalg/solvers.rs で確認した対応候補です。未接続の Rust 関数をこのプローブが直接実行したとは主張しません。

  • この表は全 BLAS / LAPACK の網羅検証ではありません。特異行列、非有限値、一般化固有値、他 OS の結果も含みません。

  • LP64 の直接 ABI テストや負ストライド等の既存回帰テストとは別の、Julia 高水準 API の確認です。

Householder ABI 接続（#264） ​

この追記は既存の Linux 実測表とは別の検証です。Julia 1.13.3 / x86_64-apple-darwin、colmat-rs e1c83482f5a61449d30e989808c3ba5f751ec391 を使用しました。 test/householder.jl は larf/larfx/larfy/larft/larfb/larfg/larfgp の 4型・LP64/ILP64 の共有ライブラリ入口を具体的な C 署名で実行し、 28 canonical シンボルの LBT 登録先が Colmat であることを確認します。

生成は LAPACK の I - tau*v*v'、実数 beta、LARFGP の非負 beta に合わせた Rust adapter です。colmat の実数係数・複素位相を保持する生成 API の単なる 逆数変換ではありません。適用は既存の native GEMV/SYMV/GEMM を使用します。 F/B、C/R の implicit unit diagonal を展開し、LARFT の三角因子を構成します。 LARFB は LAPACK 形式の外部因子も受け入れます。

検証は反射積・ユニタリ性・極小/極大尺度・複素 head・ゼロ係数・ 長さ1・正負 stride・左右・上下三角・外部 OpenBLAS の LARFT 因子を含みます。 LARFX の小次数では WORK を参照せず、LARFY は選択した三角領域だけを更新します。 これらの補助ルーチンには workspace query や INFO 引数はありません。 不正引数の診断は既存の colmat_blas_last_error 規約を使います。

LARFB は内部で basis と次数の二乗の明示的な反射行列を確保します。 呼び出し側の最小合法 WORK で動作しますが、作業領域だけを使う実装や LAPACK と同じ計算量・割り当て量を保証するものではありません。 この接続は Fortran ABI に限定し、LAPACKE は別タスクです。

Compact QR 接続（#290） ​

Julia 1.13.3 / x86_64-apple-darwin と上記固定 colmat-rs revision で、 通常の qr(A)、Matrix(F.Q)、Q/Q' の左右適用を Colmat の GEQRT/GEMQRT 入口に接続しました。既存 Linux snapshot の未接続という 記録は、その時点の結果として保持しています。

test/qr_compact.jl は4型、LP64/ILP64 の具体的な C 署名、NB=1/2/4、 GEQRT2/GEQRT3、外部 OpenBLAS の因子との双方向相互運用、leading dimension、 空行列、ゼロ列・従属列、極小尺度、不正引数を検証します。 これらの入口には LWORK query はありません。WORK は標準の最小長で実行します。

native QR は各 active column に適用し、実数の native 係数の逆数から LAPACK の T を構成します。これにより、native の rank 処理がゼロ列を 詰める場合も LAPACK の対角位置を保ちます。複素 R の対角位相を保持し、 Q と R の積・外部 LAPACK による反射適用を検証します。 GEQRT3 も共通の数値経路を使い、Netlib の再帰算法とは異なります。 内部配列を確保し、GEMQRT は各ブロックを明示的に展開します。

通常 QR 接続（#289） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GEQRF/GEQR2、非負対角版、ORGQR/UNGQR/ORG2R/UNG2R、 ORMQR/UNMQR/ORM2R/UNM2R、GEQRS の36シンボルを両整数 ABI に接続しました。 test/qr_standard.jl は Julia ラッパー経由の再構成・Q の左右適用に加え、 両 ABI の直接実行、外部 OpenBLAS 因子の受け入れと native 因子の外部適用、 非負対角、workspace query と最小合法作業領域、padded leading dimension、 空・矩形・ゼロ列、GEQRS の最小二乗残差を検証します。

実数通常版は native QR の block-size-one 係数から A/TAU を作ります。 複素通常版と非負対角版は LAPACK gauge reflector 生成を使い、 実数 beta と複素 TAU を Julia の標準規約に合わせます。 Q の適用は native GEMV、GEQRS の三角 solve は native 三角 kernel に接続します。 内部配列を確保するため、呼び出し側の WORK 以外にもメモリを使用します。 GEQRS は deprecated LAPACK 契約に従い、workspace query を提供しません。

列ピボット QR 接続（#299） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GEQP3/GEQPF/GEQP3RK の12シンボルを4型・両整数 ABI に接続しました。 qr(A, ColumnNorm()) は GEQP3 から native QR/reflector 適用へ到達します。 固定 JPVT 列は入力順を保って先頭へ移し、出力は元の列番号を1始まりで返します。

GEQP3RK は KMAX と、残差部分の最大列2ノルムに対する ABSTOL/RELTOL で停止します。 各段階で列ノルムを再計算するため、native ColPivQr の対角値による rank 判定や Netlib の部分ノルム更新とは異なる計算量・丸め経路です。付随 NRHS 列は ピボット選択から除外し、Q' を適用します。NaN/Inf の INFO、ゼロ・極小 tolerance、 rank と残差ノルムの返却を別々に扱います。内部配列を確保します。

test/qr_pivoted.jl で両 ABI の具体的な C 署名、固定列、外部 OpenBLAS 因子、 途中停止した分解の再構成、独立計算した残差ノルム、付随右辺、 query と最小合法 workspace、leading dimension、空行列・1×1・ゼロ行列、 NaN/Inf 診断、LBT 登録を検証します。空行列の Julia GEQP3 ラッパーは native 入口を呼ばないため、直接 ABI の空行列ケースと区別します。

LQ 接続（#291） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 通常・ブロック・short-wide・ヘッダー形式の LQ、Q の生成・左右適用、 GELQS の56シンボルを4型・両整数 ABI に接続しました。 通常 LQ は随伴 QR の恒等式を使い、A/TAU と行保存のブロック T を構成します。 short-wide 形式は最初の NB 列の因子と、後続の [L B] パネルの因子を LAPACK と同じ順序で格納します。外部の T とヘッダーを受け入れます。

GELQ は合法な MB=1・NB=N の形式を選ぶため、最適・最小 query の推奨値が 一致します。GELQT3 は共通の分解経路であり Netlib の再帰算法ではありません。 内部で随伴行列・反射・選択パネルなどを確保します。GELQS は deprecated LAPACK 契約に従い workspace query を提供しません。

test/lq.jl は4型・両 ABI、通常 Julia ラッパー、最小合法 workspace、 最小ヘッダー query、ブロック端、外部 OpenBLAS 因子との双方向相互運用、 左右・転置・共役、leading dimension の padding、空・矩形・階数落ち、 GELQS の残差と最小ノルム性、56シンボルの LBT 登録を検証します。

RZ 接続（#304） ​

test/rz.jl は両 ABI の直接呼び出し、Julia ラッパー、外部 OpenBLAS の 因子・適用との相互運用、query と最小合法 workspace、padding、正負 stride、 分離された C1/C2、L=0 と暗黙成分に重なる尾部、中央領域を NaN にした入力、 直交性・再構成・共役適用と LBT 登録を検証します。

最小二乗 driver 接続（#310） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GELS/GELST/GETSLS、GELSS/GELSD、GELSY/GELSX の28シンボルを4型・両整数 ABI に接続しました。 full-rank 系は QR/LQ と三角 solve で tall/wide と転置・共役を処理し、 A/B を尺度調整して解・残差・因子の尺度を戻します。 GELSS/GELSD は共通 native SVD で RCOND と rank を判定します。 GELSS の A には行方向の右特異ベクトルを返します。GELSD の query は WORK に加え IWORK/RWORK の必要長を返します。

GELSY/GELSX は固定 JPVT の列ピボット QR、leading R の条件判定、RZ、 Q/Z 適用、逆置換による完全直交分解です。条件判定には leading R の 特異値を使うため、Netlib の増分条件推定とは境界付近の rank が異なる可能性があります。 GELST/GETSLS は共通 full-rank 経路で、Netlib の compact-WY/TS 算法と同一ではありません。 GETSLS は最適・最小 query の値が一致する構成です。SVD の full U や中間行列などを 内部で確保し、GELSD という名称でも native divide-and-conquer の実行を保証しません。

test/least_squares.jl は両 ABI の具体的な C 署名、外部 OpenBLAS との比較、 固定列、rank-deficient と過少決定の最小ノルム解、特異値・右特異ベクトル、 TRANS/共役、残差配置、極小/極大尺度、padding、最小 workspace と query、 空・ゼロ入力、28シンボルの LBT 登録を検証します。

Schur driver 接続（#300） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 HSEQR/LAHQR/LAQR0/LAQR4/GEES の20シンボルを4型・両整数 ABI に接続しました。 Hessenberg の active block を公開 native Schur API へ渡し、範囲外との結合と 既存 Z を native GEMM で更新します。COMPZ=N/I/V、JOB=E/S、 補助入口の WANTT/WANTZ と ILOZ/IHIZ を扱います。JOB=E/WANTT=false でも Schur 形式まで計算します。各入口は同じ native QR 経路を使い、Netlib の LAHQR/LAQR0/LAQR4 の算法の切り替えを再現するものではありません。

GEES は Hessenberg 還元、native Schur、native block reorder を合成します。 尺度を正規化してから還元・反復・並べ替えを行い、SELECT には元の単位の 固有値を渡します。SELECT の Fortran LOGICAL は整数 ABI と同じ幅で扱い、 実数共役対は片方が選択されれば両方を選択します。SDIM と選択された スペクトルの前方配置を返し、並べ替え拒否と再選択の不整合はそれぞれ INFO=N+1/N+2 です。SORT=N と workspace query では callback を呼びません。 GEESX/TRSEN の条件推定はこの接続に含みません。

公開 native Schur API は非収束の部分 index を返しません。その場合は active range 全体を未収束として INFO=IHI を返し、部分収束を偽って報告しません。 内部で行列・反射係数・native scratch を確保し、呼び出し元の最小合法 WORK で 実行できます。query はその必要長を返します。

test/schur.jl は4型・両 ABI の具体的な C 署名、Julia の通常ラッパー、 A=Z_T_Z'、直交性、active range、既存 Z の更新と行範囲、実 Schur 共役対、 SELECT/SDIM、極小・極大尺度、padding、未参照領域の NaN、空・1×1、 query、不正引数、非収束 INFO と20シンボルの LBT 登録を検証します。

QZ driver 接続（#294） ​

SBTRD/HBTRD/SPTRD/HPTRD と OPGTR/UPGTR/OPMTR/UPMTR の16 Fortran シンボルを 4型・LP64/ILP64 に接続します。各 ABI は1250シンボル（BLAS 202、LAPACK 1048）です。 native revision は 4e6ed0e34659147a5c744ab6431f150e78db6f82 のままです。

SPTRD/HPTRD は選択三角だけを所有行列へ展開し、既存 native reduction の実 beta gauge を LAPACK の packed AP/TAU 形式へ戻します。複素対角の虚部を読みません。Q の生成・適用は 既存の native Householder 適用を共有し、packed 尾部を直接集めます。暗黙の1、対角、 三重対角成分、係数ゼロの reflector の尾部を読みません。AP/TAU は参照 LAPACK で生成した 因子とも相互利用でき、OPMTR/UPMTR は左右適用・転置/共役転置に対応します。

SBTRD/HBTRD も所有行列へ展開して同じ reduction を用い、D/E と band の対角・隣接対角を 返します。VECT=V は Q、VECT=U は呼び出し元の X に対する X*Q、VECT=N は Q を参照しません。 複素 E は列位相を Q に反映して非負の実数へ戻します。KD=0/1 の実数経路は元の 三重対角形と恒等 Q を保持します。専用 band bulge chase と同じ計算量や性能は主張せず、 所有行列の領域は O(n²) です。

固定 WORK の最小領域、INFO、空/単一要素、ゼロ・階数1・重複スペクトル、leading dimension、 未使用 band 領域、Q と行列 padding を検証します。test/structured_tridiagonal_*.jl は A≈Q_T_Qᴴ、QᴴQ≈I、外部 AP/TAU との相互利用、既存行列の更新と LBT の実転送を確認します。

Schur 形式からの左右固有ベクトル（Issue #311） ​

TREVC/TREVC3 の8 Fortran シンボルを4型・LP64/ILP64 に接続します。 各 ABI は1258シンボル（BLAS 202、LAPACK 1056）で、native revision は 4e6ed0e34659147a5c744ab6431f150e78db6f82 のままです。

右側は公開 eigenvectors_from_schur_real/cplx を使います。左側は Schur 形式の 反転した転置/随伴を上三角形式として同じ helper に渡し、行・列を元の順へ戻します。 実数2x2ブロックでは正の虚部に対応する列対の順序と左側の共役を明示します。 Schur 形を再計算せず、入力 T の指定三角と実数の第一副対角だけを読みます。

SIDE=L/R/B、HOWMNY=A/B/S、実数対の SELECT の標準化、M/MM、Q_X と Q_Y の back-transform を保持します。単独列の最大 abs1 成分、実数対の最大 |re|+|im| を1へ 正規化します。指定外の VL/VR、選択外の列、T と padding を変更しません。 SELECT は HOWMNY=S の実数対だけ書き換え、複素 SELECT は入力専用です。

TREVC3 は同じ native helper と行列積を共有し、Netlib 固有の blocked back-substitution 算法を実装したという意味ではありません。固定 WORK と最小合法 LWORK/LRWORK、 collective query、実数/複素で異なる検査順序を保持します。query はこの経路で十分な 最小領域を返し、参照 LAPACK の block size に基づく推奨値と一致する保証はありません。 所有行列と native scratch は O(n²) です。native 拒否時は VL/VR を変更する前に保存済みの 元の ILP64 TREVC/TREVC3 へ渡し、LP64 の SELECT/M/INFO は専用整数領域で変換します。

test/schur_vectors*.jl は左右の独立残差、実数共役対の packing と正規化、M/MM、 SELECT、back-transform、空・単一要素・ゼロ・重複固有値、極小/極大スケール、厳密な 最小 work・query・不足時 INFO、格納 guard と実際の LBT 転送を検証します。

通常 Schur block の並べ替えと条件推定（Issue #312） ​

TREXC/LAEXC/TRSEN/GEESX の14 Fortran シンボルを LP64/ILP64 に接続します。 TREXC/TRSEN/GEESX は4型、LAEXC は実数2型です。各 ABI は1272シンボル （BLAS 202、LAPACK 1070）で、native revision は 4e6ed0e34659147a5c744ab6431f150e78db6f82 のままです。

TREXC/LAEXC は公開 native checked Schur move を使い、1x1/2x2 の block 交換、 既存 Q への変換の蓄積、実数 IFST/ILST の先頭行補正と最終位置を保持します。 複素 TREXC の IFST/ILST は入力専用として保持します。拒否した交換を取り消し、 最後に成功した交換までの T/Q と現在位置を返します。LAEXC は N または block 幅が ゼロの場合にデータを参照しません。内部では所有 Schur 行列と必要な Q を確保します。

TRSEN JOB=N は SELECT を変更せず、実数共役対をまとめて安定選択し、M と固有値、 必要な Q を返します。虚部は off-diagonal の平方根を別々に計算し、大きい実部の隣の 小さい虚部を相対スケーリングで失わないようにします。LWORK=-1 だけが query で、 LIWORK=-1 単独は実数版の不足引数です。実数 JOB=N の最小 WORK は max(1,N)、 複素 JOB=N は1、実数 IWORK は1です。

GEESX SENSE=N は既存 native GEES と同じ数値経路を使います。交換拒否時の SDIM は 移動済み prefix ではなく全選択列数を返すよう GEES 共通処理も修正しました。 SORT=N や query では SELECT を呼びません。実数 GEESX は LWORK/LIWORK のどちらかが -1 なら collective query、複素版は LWORK=-1 だけが query です。native 経路の query は その経路で十分な最小 WORK を返し、参照実装の block size による推奨値とは限りません。

S/SEP と RCONDE/RCONDV の公開 native 数値 API はないため、TRSEN JOB=E/V/B と GEESX SENSE=E/V/B は保存した元の ILP64 routine を使います。LP64 では SELECT、M、 SDIM、INFO と整数・論理作業配列を変換し、IWORK/BWORK は書き込み済み slot だけ戻します。 SELECT callback の LOGICAL 戻り値は thread-local guard で変換し、入れ子呼び出し後に 外側の callback を復元します。元の routine の不正引数 INFO は adapter の診断にも記録し、 正の数値的拒否を不正引数として扱いません。

test/ordinary_schur_*.jl は4型と両 ABI、全 block サイズと移動方向、選択順、相似変換、 Q の直交/ユニタリ性、有限値での拒否と途中状態、全選択列数、最小 workspace と query、 元の条件推定、callback の元の単位・実数対・入れ子呼び出し、未参照出力・padding・ 整数 guard、および各入口の実際の LBT 転送を検証します。

一般化 QR と等式制約付き driver（Issue #314） ​

GGQRF/GGRQF/GGLSE/GGGLM の全16 Fortran シンボルを実数・複素数4型、 LP64/ILP64 の両方で接続します。依存 revision は 4e6ed0e34659147a5c744ab6431f150e78db6f82 のままです。

GGQRF は A=Q R, B=Q T Z、GGRQF は A=R Q, B=Z T Q を、既存の native-backed QR/RQ と Q の適用から構成します。返す reflector は元の LAPACK の ORG/UNGQR/RQ からも Q を生成でき、矩形・空・ゼロ・階数1入力の両行列を再構成できます。 複素数の Q 適用には転置ではなく随伴を使います。三角 solve は公開 native solve を使い、 complex scalar の直接除算で分母を二乗して極端値が NaN になる経路を避けます。

GGLSE は min ||c-Ax||₂, Bx=d、GGGLM は min ||y||₂, Ax+By=d を解きます。 それぞれ 0≤P≤N≤M+P、0≤M≤N≤M+P の次元制約を検査します。 最初の制約系 triangular factor が厳密に特異なら INFO=1、残る自由変数の triangular factor が厳密に特異なら INFO=2 です。これは rank-revealing tolerance による数値階数推定ではありません。失敗時は既に行った因子化・右辺変換を保持し、 まだ求めていない解を成功値として返しません。C/D の残差・中間解 payload も破壊的に更新します。

LWORK=-1 は query で、入力行列・右辺・解・TAU を変更しません。 GGQRF/GGRQF の最小 WORK は max(1,N,M,P)、GGLSE/GGGLM は通常 M+N+P、 解く系の N が0なら1です。query は adapter の合法な最小値を返し、Netlib の block-size による推奨値との一致は要求しません。補助行列・係数・native scratch は adapter 内で別途確保します。専用 colmat-rs driver や Netlib と同じ算法・性能を 提供するという意味ではありません。

独立参照の元の OpenBLAS driver に対する解の比較に加え、制約残差、自由方向の stationarity、最小ノルム性、外部 Q による再構成、WORK/INFO/TAU と padding の境界、 query、引数順序、厳密な rank failure を検査します。LBT の provider と関数ポインタを 実際に取得して各16入口を両 ABI で呼ぶ検査を含みます。実装の driver 更新順序は Reference LAPACK v3.12.1 SRC/dgglse.f / SRC/dggglm.f を参照し、出典と BSD-3-Clause license を deps/rust/src/constrained_least_squares.rs と deps/rust/licenses/ に記録しています。

GEEVX の expert mode と能力確認（Issue #316） ​

SENSE=N の native 経路を保ち、SENSE=E/V/B は保存した元の実装へ委譲します。 LP64 の元の実装がある場合はそのまま呼び、ない場合は保存した ILP64 実装を使います。 N/LDA/LDVL/LDVR/LWORK を拡張し、ILO/IHI/INFO と実数 IWORK を検査付きで戻します。 query や参照しない IWORK slot、出力を元の実装が書かなかった場合は呼び出し側の値を保持します。 複素 RWORK は同じ実数型の scratch として渡します。内部 TREVC3 query が RWORK を更新する場合があります。

load_backend() は4型の元の ILP64 GEEVX を LBT 変更前に確認し、不足すれば設定エラーを返します。 既存の LP64 実装がない通常の Julia 環境でも、ILP64 実装を通して合法な expert mode を利用できます。 SENSE='?' や E/B で左右両方の固有ベクトルを要求しない組み合わせは、引数4の不正として扱います。 再登録時に Colmat の各 GEEVX 自身を fallback として保存しません。

低水準 DLL を直接利用する場合、expert call の前に元の実装を登録する必要があります。 colmat_lapack_has_expert_fallback(id,bits) は id=0/1/2/3（s/d/c/z）、bits=32/64 を受け、 利用可能なら1を返します。LP64 では保存した ILP64 経路も利用可能性に含みます。 未設定のまま合法な expert call を行った場合は、INFO と計算出力を変更せず、 colmat_blas_last_error() に設定診断 -1 を記録します。外部整数出力が ABI の範囲外なら診断 -2 です。 通常の Julia では登録時の検査がこの未設定状態を防ぎます。独自の LAPACK INFO 値を追加せず、 条件推定を計算せずに成功値を返すことや、C ABI を越える例外の unwind を行いません。

4型・両 integer ABI、通常計算/query、balance・左右固有ベクトル・全 SENSE、 最小 WORK、不正引数の順序、padding/整数 guard を検査します。独立参照と左右の残差・ 非ゼロ正規化・条件推定を比較し、LP64 の直接委譲はテスト専用 OpenBLAS32_jll でも検査します。 ILP64 のみで LP64 を処理する構成、元の実装の消去と回復、初回登録前の欠落を独立プロセスで確認します。 数値 API の依存 revision は 4e6ed0e34659147a5c744ab6431f150e78db6f82、この #316 検証時点の登録数は各 ABI 1,288 です。

Direct LP64/ILP64 execution evidence (#317) ​

The normal full suite checks completed project-owned foreign calls for all 1,106 forwarded LAPACK canonical entries in each integer ABI. The execution snapshot records exact source and native revisions, platform, Julia version, binary hash, source hashes and individual DLL/LBT routes and signatures. Linux/macOS CI saves separate artifacts from the same gate.

The original 76-symbol driver baseline additionally tests guarded integer and floating outputs, padded leading dimensions, empty/rectangular/singular cases, query and exact minimum work, solves/inverses, SVD full/thin/overwrite modes, left/right eigenvectors and selfadjoint index/value selections. OpenBLAS calls use independent ILP64 signatures; reconstruction, residuals and orthogonality are checked against original inputs. The isolated C caller checks wrong-width INFO writes in both directions, with a real protected-page crash confined to a child process.

direct_call_witness means a concrete entry call returned. It does not claim all options, the identity of Netlib algorithms or native sanitizer coverage. The importer rejects stale production/worker/test sources, native revisions, manifests, registration inventories and missing integer ABIs. Other symbols remain not_catalogued, which does not mean they were never tested.

ROOK 因子と2つの swap index（#372） ​

SY/HE TRF_ROOK・TF2_ROOK・TRS_ROOK・TRI_ROOK・SV_ROOK の20シンボルを、 4型・両整数 ABI・UPLO 両方向で検証します。DLL と実際の LBT stub を呼び、 native 因子を元の OpenBLAS solve/inverse に、元の因子を native に渡します。 2列 pivot の両 swap が非自明になる連鎖、要素的な置換・三角行列の積による再構成、 特異 INFO、query/minimum WORK、整数・padding 境界を含みます。

subnormal の native 逆数化は非有限値を作る場合があり、実行済み MWE と改善案を tensor4all/colmat-rs#212 に記録しています。 adapter は公開数値 API の合成とスケーリングで保護します。通常・packed BK と共有し、 異なる単位をまたぐ非零 L と、有限で既知の解も検証しています。 元の OpenBLAS classic 因子化自体が失敗する subnormal 多 block の条件では、 その出力を正解とせず、要素ごとの再構成と単位行列解で検査します。 専用算法・同じ pivot 選択・性能や、表現範囲外の有限 inverse は主張しません。
