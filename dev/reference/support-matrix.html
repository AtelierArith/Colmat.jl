Julia API の実測対応表 ​

通常配列の呼び出しが成功するかと、その入口を Colmat が提供するかを分けて記録します。 入口は Julia 1.13 のラッパー実装から選び、LBT の登録先を照合します。動的な呼び出し回数の計測やライブラリ内部を追跡したトレースではありません。

検証条件 ​

  • Julia: 1.13.3 / x86_64-linux-gnu。

  • Colmat ソース: bc0dce2af48590dec20f99976ad7aee8b999a447。

  • Rust colmat ソース: e1c83482f5a61449d30e989808c3ba5f751ec391。

  • Julia の BLAS 整数 ABI: ilp64。

  • Colmat 実行幅: 1。

  • 要素型は Float32 / Float64 / ComplexF32 / ComplexF64 の順。

判定の範囲 ​

  • 「成功」は、このプローブの小さな有限値入力で参照計算または分解の残差を満たしたことを表します。

  • 行列積・求解・分解再構成の残差は、BLAS を呼ばないスカラーの積和で確認します。

  • 「既存バックエンド」での成功は、Rust colmat の該当分解が接続済みであるという意味ではありません。

  • Rust 側の機能名は固定 revision の faer/src/linalg/solvers.rs で確認した対応候補です。未接続の Rust 関数をこのプローブが直接実行したとは主張しません。

  • この表は全 BLAS / LAPACK の網羅検証ではありません。特異行列、非有限値、一般化固有値、他 OS の結果も含みません。

  • LP64 の直接 ABI テストや負ストライド等の既存回帰テストとは別の、Julia 高水準 API の確認です。

Householder ABI 接続（#264） ​

この追記は既存の Linux 実測表とは別の検証です。Julia 1.13.3 / x86_64-apple-darwin、colmat-rs e1c83482f5a61449d30e989808c3ba5f751ec391 を使用しました。 test/householder.jl は larf/larfx/larfy/larft/larfb/larfg/larfgp の 4型・LP64/ILP64 の共有ライブラリ入口を具体的な C 署名で実行し、 28 canonical シンボルの LBT 登録先が Colmat であることを確認します。

生成は LAPACK の I - tau*v*v'、実数 beta、LARFGP の非負 beta に合わせた Rust adapter です。colmat の実数係数・複素位相を保持する生成 API の単なる 逆数変換ではありません。適用は既存の native GEMV/SYMV/GEMM を使用します。 F/B、C/R の implicit unit diagonal を展開し、LARFT の三角因子を構成します。 LARFB は LAPACK 形式の外部因子も受け入れます。

検証は反射積・ユニタリ性・極小/極大尺度・複素 head・ゼロ係数・ 長さ1・正負 stride・左右・上下三角・外部 OpenBLAS の LARFT 因子を含みます。 LARFX の小次数では WORK を参照せず、LARFY は選択した三角領域だけを更新します。 これらの補助ルーチンには workspace query や INFO 引数はありません。 不正引数の診断は既存の colmat_blas_last_error 規約を使います。

LARFB は内部で basis と次数の二乗の明示的な反射行列を確保します。 呼び出し側の最小合法 WORK で動作しますが、作業領域だけを使う実装や LAPACK と同じ計算量・割り当て量を保証するものではありません。 この接続は Fortran ABI に限定し、LAPACKE は別タスクです。

Compact QR 接続（#290） ​

Julia 1.13.3 / x86_64-apple-darwin と上記固定 colmat-rs revision で、 通常の qr(A)、Matrix(F.Q)、Q/Q' の左右適用を Colmat の GEQRT/GEMQRT 入口に接続しました。既存 Linux snapshot の未接続という 記録は、その時点の結果として保持しています。

test/qr_compact.jl は4型、LP64/ILP64 の具体的な C 署名、NB=1/2/4、 GEQRT2/GEQRT3、外部 OpenBLAS の因子との双方向相互運用、leading dimension、 空行列、ゼロ列・従属列、極小尺度、不正引数を検証します。 これらの入口には LWORK query はありません。WORK は標準の最小長で実行します。

native QR は各 active column に適用し、実数の native 係数の逆数から LAPACK の T を構成します。これにより、native の rank 処理がゼロ列を 詰める場合も LAPACK の対角位置を保ちます。複素 R の対角位相を保持し、 Q と R の積・外部 LAPACK による反射適用を検証します。 GEQRT3 も共通の数値経路を使い、Netlib の再帰算法とは異なります。 内部配列を確保し、GEMQRT は各ブロックを明示的に展開します。

通常 QR 接続（#289） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GEQRF/GEQR2、非負対角版、ORGQR/UNGQR/ORG2R/UNG2R、 ORMQR/UNMQR/ORM2R/UNM2R、GEQRS の36シンボルを両整数 ABI に接続しました。 test/qr_standard.jl は Julia ラッパー経由の再構成・Q の左右適用に加え、 両 ABI の直接実行、外部 OpenBLAS 因子の受け入れと native 因子の外部適用、 非負対角、workspace query と最小合法作業領域、padded leading dimension、 空・矩形・ゼロ列、GEQRS の最小二乗残差を検証します。

実数通常版は native QR の block-size-one 係数から A/TAU を作ります。 複素通常版と非負対角版は LAPACK gauge reflector 生成を使い、 実数 beta と複素 TAU を Julia の標準規約に合わせます。 Q の適用は native GEMV、GEQRS の三角 solve は native 三角 kernel に接続します。 内部配列を確保するため、呼び出し側の WORK 以外にもメモリを使用します。 GEQRS は deprecated LAPACK 契約に従い、workspace query を提供しません。

列ピボット QR 接続（#299） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GEQP3/GEQPF/GEQP3RK の12シンボルを4型・両整数 ABI に接続しました。 qr(A, ColumnNorm()) は GEQP3 から native QR/reflector 適用へ到達します。 固定 JPVT 列は入力順を保って先頭へ移し、出力は元の列番号を1始まりで返します。

GEQP3RK は KMAX と、残差部分の最大列2ノルムに対する ABSTOL/RELTOL で停止します。 各段階で列ノルムを再計算するため、native ColPivQr の対角値による rank 判定や Netlib の部分ノルム更新とは異なる計算量・丸め経路です。付随 NRHS 列は ピボット選択から除外し、Q' を適用します。NaN/Inf の INFO、ゼロ・極小 tolerance、 rank と残差ノルムの返却を別々に扱います。内部配列を確保します。

test/qr_pivoted.jl で両 ABI の具体的な C 署名、固定列、外部 OpenBLAS 因子、 途中停止した分解の再構成、独立計算した残差ノルム、付随右辺、 query と最小合法 workspace、leading dimension、空行列・1×1・ゼロ行列、 NaN/Inf 診断、LBT 登録を検証します。空行列の Julia GEQP3 ラッパーは native 入口を呼ばないため、直接 ABI の空行列ケースと区別します。

LQ 接続（#291） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 通常・ブロック・short-wide・ヘッダー形式の LQ、Q の生成・左右適用、 GELQS の56シンボルを4型・両整数 ABI に接続しました。 通常 LQ は随伴 QR の恒等式を使い、A/TAU と行保存のブロック T を構成します。 short-wide 形式は最初の NB 列の因子と、後続の [L B] パネルの因子を LAPACK と同じ順序で格納します。外部の T とヘッダーを受け入れます。

GELQ は合法な MB=1・NB=N の形式を選ぶため、最適・最小 query の推奨値が 一致します。GELQT3 は共通の分解経路であり Netlib の再帰算法ではありません。 内部で随伴行列・反射・選択パネルなどを確保します。GELQS は deprecated LAPACK 契約に従い workspace query を提供しません。

test/lq.jl は4型・両 ABI、通常 Julia ラッパー、最小合法 workspace、 最小ヘッダー query、ブロック端、外部 OpenBLAS 因子との双方向相互運用、 左右・転置・共役、leading dimension の padding、空・矩形・階数落ち、 GELQS の残差と最小ノルム性、56シンボルの LBT 登録を検証します。

RZ 接続（#304） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 TZRZF/TZRQF/LATRZ、ORMRZ/UNMRZ、LARZ/LATZM、LARZT/LARZB の 32シンボルを4型・両整数 ABI に接続しました。upper trapezoid の A = [R 0] Z を後ろの行から構成し、疎な反射を native GEMV/GEMM で適用します。 LARZT/LARZB は LAPACK の backward・行保存を扱い、複素 T の共役も変換します。 単反射・ブロック反射とも作用しない中央領域を保持し、内部配列を確保します。

test/rz.jl は両 ABI の直接呼び出し、Julia ラッパー、外部 OpenBLAS の 因子・適用との相互運用、query と最小合法 workspace、padding、正負 stride、 分離された C1/C2、L=0 と暗黙成分に重なる尾部、中央領域を NaN にした入力、 直交性・再構成・共役適用と LBT 登録を検証します。

最小二乗 driver 接続（#310） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GELS/GELST/GETSLS、GELSS/GELSD、GELSY/GELSX の28シンボルを4型・両整数 ABI に接続しました。 full-rank 系は QR/LQ と三角 solve で tall/wide と転置・共役を処理し、 A/B を尺度調整して解・残差・因子の尺度を戻します。 GELSS/GELSD は共通 native SVD で RCOND と rank を判定します。 GELSS の A には行方向の右特異ベクトルを返します。GELSD の query は WORK に加え IWORK/RWORK の必要長を返します。

GELSY/GELSX は固定 JPVT の列ピボット QR、leading R の条件判定、RZ、 Q/Z 適用、逆置換による完全直交分解です。条件判定には leading R の 特異値を使うため、Netlib の増分条件推定とは境界付近の rank が異なる可能性があります。 GELST/GETSLS は共通 full-rank 経路で、Netlib の compact-WY/TS 算法と同一ではありません。 GETSLS は最適・最小 query の値が一致する構成です。SVD の full U や中間行列などを 内部で確保し、GELSD という名称でも native divide-and-conquer の実行を保証しません。

test/least_squares.jl は両 ABI の具体的な C 署名、外部 OpenBLAS との比較、 固定列、rank-deficient と過少決定の最小ノルム解、特異値・右特異ベクトル、 TRANS/共役、残差配置、極小/極大尺度、padding、最小 workspace と query、 空・ゼロ入力、28シンボルの LBT 登録を検証します。

Hessenberg 接続（#293） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GEHRD/GEHD2、ORGHR/UNGHR、ORMHR/UNMHR の16シンボルを4型・両整数 ABI に接続しました。 LAPACK gauge の reflector 生成と native GEMV による左右適用で A/TAU を構成し、 複素 subdiagonal を実数にします。GEHRD/GEHD2 は共通経路で、ブロック化の差はありません。 ILO/IHI の部分範囲に対応し、Q はその範囲外で恒等変換です。 内部で反射・Q 生成用の配列を確保します。

test/hessenberg.jl は Julia ラッパー、両 ABI の具体的な C 署名、 外部 OpenBLAS の因子と Q との相互運用、A=Q_H_Q'、直交性、active range 外の 保存、空・1×1、左右・転置・共役、padding、最小 workspace と query、 不正範囲と LBT 登録を検証します。

Schur driver 接続（#300） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 HSEQR/LAHQR/LAQR0/LAQR4/GEES の20シンボルを4型・両整数 ABI に接続しました。 Hessenberg の active block を公開 native Schur API へ渡し、範囲外との結合と 既存 Z を native GEMM で更新します。COMPZ=N/I/V、JOB=E/S、 補助入口の WANTT/WANTZ と ILOZ/IHIZ を扱います。JOB=E/WANTT=false でも Schur 形式まで計算します。各入口は同じ native QR 経路を使い、Netlib の LAHQR/LAQR0/LAQR4 の算法の切り替えを再現するものではありません。

GEES は Hessenberg 還元、native Schur、native block reorder を合成します。 尺度を正規化してから還元・反復・並べ替えを行い、SELECT には元の単位の 固有値を渡します。SELECT の Fortran LOGICAL は整数 ABI と同じ幅で扱い、 実数共役対は片方が選択されれば両方を選択します。SDIM と選択された スペクトルの前方配置を返し、並べ替え拒否と再選択の不整合はそれぞれ INFO=N+1/N+2 です。SORT=N と workspace query では callback を呼びません。 GEESX/TRSEN の条件推定はこの接続に含みません。

公開 native Schur API は非収束の部分 index を返しません。その場合は active range 全体を未収束として INFO=IHI を返し、部分収束を偽って報告しません。 内部で行列・反射係数・native scratch を確保し、呼び出し元の最小合法 WORK で 実行できます。query はその必要長を返します。

test/schur.jl は4型・両 ABI の具体的な C 署名、Julia の通常ラッパー、 A=Z_T_Z'、直交性、active range、既存 Z の更新と行範囲、実 Schur 共役対、 SELECT/SDIM、極小・極大尺度、padding、未参照領域の NaN、空・1×1、 query、不正引数、非収束 INFO と20シンボルの LBT 登録を検証します。

一般化 Hessenberg 接続（#269） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 GGHRD/GGHD3 の8シンボルを4型・両整数 ABI に接続しました。 公開 generalized_hessenberg が返す active block の左右基底を全体へ埋め込み、 範囲外との結合と既存 Q/Z を native GEMM で更新します。 COMPQ/COMPZ=N/I/V と ILO/IHI を扱い、B の厳密下三角は入力で読みません。 GGHRD/GGHD3 は同じ native 経路で、内部の行列・scratch を確保します。 GGHD3 は呼び出し元の WORK を1要素だけ必要とし、query でも1を返します。 Netlib GGHRD/GGHD3 の別々の算法や外部 WORK の利用方法を再現しません。

test/generalized_hessenberg.jl は両 ABI の具体的な C 署名、4型、 Q'_A_Z=H と Q'_B_Z=T、Hessenberg/三角構造、ユニタリ性、 空・1×1・2×2、部分範囲、Q/Z の初期化・既存値への更新・未使用、 40×40 のブロック経路、padding、未参照 B/Q/Z の NaN、query、 不正引数と8シンボルの LBT 登録を検証します。

QZ driver 接続（#294） ​

Julia 1.13.3 / x86_64-apple-darwin と同じ固定 colmat-rs revision で、 HGEQZ/GGES/GGES3/GEGS の16シンボルを4型・両整数 ABI に接続しました。 HGEQZ は active block の native QZ と基底変換を合成し、 COMPQ/COMPZ=N/I/V と ILO/IHI を扱います。 JOB=E でも内部では Schur 形式まで計算します。 β の対角を非負の実数に揃え、Q/Z と pencil の変換を維持します。 α/β は homogeneous な組で返し、β=0 を有限の固有値へ置き換えません。

GGES/GGES3/GEGS は QR による B の三角化、一般化 Hessenberg 還元、native QZ を 合成します。A/B は独立に尺度を正規化し、α/β と S/T の単位を戻します。 GGES/GGES3 の SELECT は LP64/ILP64 の LOGICAL 幅で呼び、実数共役対の 片方が選択されれば両方を選択します。選択された block を native reorder で 前方へ移し、並べ替えた pencil の QZ を再評価して α/β を更新します。 query と SORT=N では callback を呼びません。並べ替え拒否は INFO=N+3、 再選択の不整合は INFO=N+2 です。GGESX/TGSEN の条件推定は対象外です。

完全ピボット LU と scaled solve（#272） ​

GETC2/GESC2 の4型、計8 Fortran シンボルを両整数 ABI に接続しました。 GETC2 は SMIN を abs_tol に指定して native full-pivot LU を実行します。 その最終置換を LAPACK の逐次 IPIV/JPIV に変換し、残る Schur complement には 完全ピボット選択・小ピボット置換を行い、native triangular solve と matmul で消去を継続します。 因子化を最後まで実行してから対角だけを置換する方式ではありません。

SMIN は max(eps × 最初の最大絶対値, floatmin/eps)、1要素の場合は floatmin/eps です。 小ピボットは正の実数 SMIN に置き換え、INFO は最後に摂動した位置を返します。 native prefix と参照 LAPACK は、同値候補の選び方や複素数の pivot score が異なるため、 IPIV/JPIV の値そのものの一致は保証しません。因子形式と再構成・solve の契約を保ちます。 Bignum の定数と最終 SMIN は対応する実数精度です。

GESC2 は行置換、unit lower solve、upper solve、逆順の列置換を行い、 元の行列に対する A x = SCALE b を満たす scaled solution を返します。 前進代入の更新前と後退代入の除算・積の前で右辺全体を縮小して overflow を防ぎます。 後退代入では U の行を対角で正規化してから native の積を使い、 未正規化の列との積だけが巨大になる不要な SCALE の縮小を避けます。 SCALE は実数精度で毎回更新し、積がゼロへ underflow した場合は右辺もゼロにします。 SCALE は参照 LAPACK と数値的に同一とは限らず、0≤SCALE≤1 と残差を検証します。

A は借用して因子化し、GESC2 は入力因子を変更しません。 内部で native scratch・行列サイズに比例する置換配列・正規化した U 行を確保し、 入力行列全体の控えは作りません。caller workspace と query はありません。 N=0 は配列に触れずに戻り、GESC2 の SCALE は1です。 アダプタは不正な N/LDA を検査し、GETC2 は負の INFO、 INFO 引数を持たない GESC2 は colmat_blas_last_error で引数番号を報告します。 GESC2 は最後の IPIV/JPIV 要素を参照しません。
