Scope of the assessment ​

  • "Success" means that the reference computation or the decomposition residual was satisfied for this probe's small finite inputs.

  • Residuals for matrix products, solves, and decomposition reconstruction are checked with scalar sum-of-products that do not call BLAS.

  • Success on the "existing backend" does not mean that the corresponding Rust colmat decomposition is connected.

  • The Rust-side capability names are candidates confirmed in faer/src/linalg/solvers.rs at the pinned revision. This does not claim that the probe directly executed Rust functions that are not connected.

  • This table is not exhaustive verification of all BLAS / LAPACK. It also does not include singular matrices, non-finite values, generalized eigenvalues, or results on other OSes.

  • This is a check of the high-level Julia API, separate from the existing regression tests such as the direct LP64 ABI tests and negative-stride tests.

Householder ABI connection (#264) ​

This addendum is a verification separate from the existing Linux measurement table. It used Julia 1.13.3 / x86_64-apple-darwin and colmat-rs e1c83482f5a61449d30e989808c3ba5f751ec391. test/householder.jl invokes the four-type, LP64/ILP64 shared-library entry points of larf/larfx/larfy/larft/larfb/larfg/larfgp with concrete C signatures, and confirms that the LBT forwarding target of the 28 canonical symbols is Colmat.

Generation is a Rust adapter matched to LAPACK's I - tau*v*v', real beta, and the non-negative beta of LARFGP. It is not a mere reciprocal conversion of colmat's generation API that preserves real coefficient and complex phase. Application uses the existing native GEMV/SYMV/GEMM. The implicit unit diagonal of F/B and C/R is expanded, and the triangular factor of LARFT is constructed. LARFB also accepts external factors in LAPACK form.

Verification covers reflector products, unitarity, minimal/maximal scales, complex heads, zero coefficients, length 1, positive and negative strides, left/right, upper/lower triangular, and LARFT factors from external OpenBLAS. For LARFX at small orders WORK is not referenced, and LARFY updates only the selected triangular region. These auxiliary routines have no workspace query or INFO argument. Diagnostics for invalid arguments use the existing colmat_blas_last_error convention.

LARFB internally allocates an explicit reflector matrix of size basis times order squared. It runs with the caller's minimal legal WORK, but this does not guarantee an implementation that uses only the workspace, nor the same operation count and allocation volume as LAPACK. This connection is limited to the Fortran ABI; LAPACKE is a separate task.

Compact QR connection (#290) ​

With Julia 1.13.3 / x86_64-apple-darwin and the pinned colmat-rs revision above, ordinary qr(A), Matrix(F.Q), and left/right application of Q/Q' were connected to Colmat's GEQRT/GEMQRT entry points. The record of "not connected" in the existing Linux snapshot is retained as the result at that point in time.

test/qr_compact.jl verifies the four types, concrete C signatures for LP64/ILP64, NB=1/2/4, GEQRT2/GEQRT3, bidirectional interoperation with external OpenBLAS factors, leading dimension, empty matrices, zero and dependent columns, minimal scale, and invalid arguments. These entry points have no LWORK query. WORK is run at the standard minimum length.

Native QR is applied to each active column, and LAPACK's T is constructed from the reciprocal of the real native coefficients. This preserves LAPACK's diagonal positions even when native rank handling compacts zero columns. The diagonal phase of a complex R is preserved, and the product of Q and R and reflector application by external LAPACK are verified. GEQRT3 also uses the common numerical path and differs from Netlib's recursive algorithm. Internal arrays are allocated, and GEMQRT expands each block explicitly.

Standard QR connection (#289) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 36 symbols of GEQRF/GEQR2, the non-negative diagonal variants, ORGQR/UNGQR/ORG2R/UNG2R, ORMQR/UNMQR/ORM2R/UNM2R, and GEQRS were connected to both integer ABIs. test/qr_standard.jl verifies reconstruction and left/right application of Q through the Julia wrapper, as well as direct execution on both ABIs, acceptance of external OpenBLAS factors and external application of native factors, non-negative diagonals, workspace query and minimal legal workspace, padded leading dimension, empty/rectangular/zero-column cases, and the least-squares residual of GEQRS.

The real standard version builds A/TAU from the block-size-one coefficients of native QR. The complex standard version and the non-negative diagonal version use LAPACK gauge reflector generation and align real beta and complex TAU with Julia's standard convention. Application of Q is connected to native GEMV, and the triangular solve of GEQRS to the native triangular kernel. Because internal arrays are allocated, memory is used beyond the caller's WORK. GEQRS follows the deprecated LAPACK contract and does not provide a workspace query.

Column-pivoted QR connection (#299) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 12 symbols of GEQP3/GEQPF/GEQP3RK were connected for the four types and both integer ABIs. qr(A, ColumnNorm()) reaches native QR/reflector application from GEQP3. Fixed JPVT columns are moved to the front while preserving the input order, and the output returns the original column numbers as 1-based values.

GEQP3RK stops on KMAX and on ABSTOL/RELTOL against the largest column 2-norm of the residual part. Because column norms are recomputed at each step, the operation count and rounding path differ from rank determination by the diagonal values of native ColPivQr and from Netlib's partial norm updates. Attached NRHS columns are excluded from pivot selection, and Q' is applied. NaN/Inf INFO, zero and minimal tolerance, and the return of rank and residual norms are handled separately. Internal arrays are allocated.

test/qr_pivoted.jl verifies concrete C signatures for both ABIs, fixed columns, external OpenBLAS factors, reconstruction of a decomposition stopped midway, independently computed residual norms, attached right-hand sides, query and minimal legal workspace, leading dimension, empty/1×1/zero matrices, NaN/Inf diagnostics, and LBT registration. Because the Julia GEQP3 wrapper for an empty matrix does not call the native entry point, this is distinguished from the empty-matrix case in the direct ABI.

LQ connection (#291) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 56 symbols of standard, blocked, short-wide, and header-form LQ, generation and left/right application of Q, and GELQS were connected for the four types and both integer ABIs. Standard LQ uses the adjoint QR identity and constructs A/TAU and a row-preserving block T. The short-wide form stores the factor of the first NB columns and the factors of the following [L B] panels in the same order as LAPACK. It accepts external T and headers.

Least-squares driver connection (#310) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 28 symbols of GELS/GELST/GETSLS, GELSS/GELSD, and GELSY/GELSX were connected for the four types and both integer ABIs. Full-rank systems handle tall/wide plus transpose and conjugate with QR/LQ and a triangular solve, scale A/B, and restore the scale of the solution, residual, and factors. GELSS/GELSD determine RCOND and rank with the common native SVD. GELSS returns row-wise right singular vectors in A. The GELSD query returns the required lengths of IWORK/RWORK in addition to WORK.

GELSY/GELSX is a complete orthogonal decomposition by column-pivoted QR with fixed JPVT, condition determination of the leading R, RZ, application of Q/Z, and inverse permutation. Because the singular values of the leading R are used for condition determination, the rank near a boundary may differ from Netlib's incremental condition estimation. GELST/GETSLS use the common full-rank path and are not identical to Netlib's compact-WY/TS algorithm. GETSLS is configured so that the optimal and minimal query values coincide. The full U of the SVD and intermediate matrices are allocated internally, and the name GELSD does not guarantee execution of the native divide-and-conquer.

test/least_squares.jl verifies concrete C signatures for both ABIs, comparison with external OpenBLAS, fixed columns, minimum-norm solutions for rank-deficient and underdetermined systems, singular values and right singular vectors, TRANS/conjugate, residual placement, minimal/maximal scales, padding, minimal workspace and query, empty/zero inputs, and LBT registration of the 28 symbols.

Schur driver connection (#300) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 20 symbols of HSEQR/LAHQR/LAQR0/LAQR4/GEES were connected for the four types and both integer ABIs. The active block of the Hessenberg form is passed to the public native Schur API, and coupling with the outside range and the existing Z are updated with native GEMM. COMPZ=N/I/V, JOB=E/S, and WANTT/WANTZ and ILOZ/IHIZ of the auxiliary entry points are handled. Even with JOB=E/WANTT=false it computes through to Schur form. Each entry point uses the same native QR path and does not reproduce the switching among the Netlib LAHQR/LAQR0/LAQR4 algorithms.

GEES composes Hessenberg reduction, native Schur, and native block reorder. It normalizes the scale before reduction, iteration, and reordering, and passes eigenvalues in the original units to SELECT. The Fortran LOGICAL of SELECT is handled with the same width as the integer ABI, and for a real conjugate pair both are selected if one is selected. It returns SDIM and the forward placement of the selected spectrum, and a rejected swap and an inconsistency in reselection are INFO=N+1/N+2 respectively. SORT=N and workspace query do not call the callback. Condition estimation of GEESX/TRSEN is not included in this connection.

The public native Schur API does not return a partial index for non-convergence. In that case it returns INFO=IHI treating the whole active range as non-converged, and does not falsely report partial convergence. It allocates matrices, reflector coefficients, and native scratch internally and can run with the caller's minimal legal WORK. The query returns that required length.

test/schur.jl verifies concrete C signatures for the four types and both ABIs, the ordinary Julia wrapper, A=Z_T_Z', orthogonality, the active range, updating the existing Z and row ranges, real Schur conjugate pairs, SELECT/SDIM, minimal/maximal scales, padding, NaN in unreferenced regions, empty/1×1, query, invalid arguments, non-convergence INFO, and LBT registration of the 20 symbols.

QZ driver connection (#294) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 16 symbols of HGEQZ/GGES/GGES3/GEGS were connected for the four types and both integer ABIs. HGEQZ composes the native QZ of the active block with basis transformations and handles COMPQ/COMPZ=N/I/V and ILO/IHI. Even with JOB=E it computes through to Schur form internally. It makes the diagonal of β non-negative real and preserves the transformations of Q/Z and the pencil. α/β are returned as homogeneous pairs, and β=0 is not replaced with a finite eigenvalue.

GGES/GGES3/GEGS compose triangularization of B by QR, generalized Hessenberg reduction, and native QZ. A/B are independently scale-normalized, and the units of α/β and S/T are restored. The SELECT of GGES/GGES3 is called with the LP64/ILP64 LOGICAL width, and both members of a real conjugate pair are selected if one is selected. The selected blocks are moved forward with native reorder, and the QZ of the reordered pencil is re-evaluated to update α/β. Query and SORT=N do not call the callback. A rejected swap is INFO=N+3 and an inconsistency in reselection is INFO=N+2. Condition estimation of GGESX/TGSEN is out of scope.

The public native QZ API does not return a non-convergence state or partial index. It checks the finiteness of the returned Schur structure and of each component of the homogeneous α/β, and treats an incomplete result as non-convergence of the whole active range with INFO=IHI. It allocates internal matrices and scratch and provides LAPACK's minimal legal WORK and a query for each entry point. GGES/GGES3/GEGS use a common path and do not reproduce the blocking or permutation balancing implementations of the individual Netlib drivers.

test/qz.jl verifies concrete C signatures for both ABIs, the four types, reconstruction of the pencil, Schur structure, unitarity, the active range, initialization/update/unused state of Q/Z, 40×40 input, independent OpenBLAS comparison of homogeneous values, β=0, real conjugate pairs, SELECT/SDIM, independent minimal/maximal scales, padding, NaN in unreferenced regions, empty/1×1/2×2, query and minimal WORK, invalid arguments, non-convergence INFO, the Julia GGES wrapper, and LBT registration of the 16 symbols.

Generalized EVD driver connection (#301) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 16 symbols of GGEV/GGEV3/GEGV/GGEVX were connected for the four types and both integer ABIs. The ordinary driver converts the homogeneous α/β and left/right eigenvectors of the public gevd_real/cplx. It preserves β=0 and the 0/0 singular pencil and returns a real conjugate pair in adjacent real-part and imaginary-part columns. The native real transpose-left convention is converted to LAPACK's adjoint-left convention by reversing the imaginary-part columns, and the largest |Re|+|Im| of each vector is normalized to 1. Each entry point uses the same native path and internal scratch and returns the minimal WORK/query for that entry point. When native GEVD returns non-convergence, INFO=N is set because there is no partial index.

BALANC=N/SENSE=N of GGEVX is native. It returns ILO/IHI=1/N, LSCALE/RSCALE=1, and ABNRM/BBNRM of the original matrices. The Schur output for A/B is returned to the original units by tracking the power-of-two prescale of the native implementation at the pinned revision. This conversion must be re-verified when dependencies are updated.

The other BALANC/SENSE combinations are delegated to the existing ILP64 expert backend. On LP64 calls, integer scalars are converted to 64 bit, and IWORK/BWORK are allocated within the call so that 64-bit values are not written into 32-bit output areas. ILO/IHI/INFO are restored to the original width, and ILO/IHI are not modified during a query. Balance and condition estimation are not treated as natively supported. A four-type ILP64 GGEVX is required before loading Colmat. Ordinary Julia provides OpenBLAS. If it is missing, an explicit configuration error is returned before changing the LBT registration; legal modes are not reported as invalid arguments, and uncomputed condition estimates are not treated as success. Re-registration does not save Colmat itself as the expert backend.

test/generalized_eigen.jl verifies the four types, both ABIs, and all four entry points; left/right/single-sided/values-only; homogeneous left and right residuals; β=0; 0/0; real conjugate pairs and normalization; independent OpenBLAS comparison; all BALANC/SENSE combinations of GGEVX; metadata; query; integer-width guards; padding; Schur output in the original scale; empty/1×1; insufficient workspace; and LBT registration. A separate process also checks the pre-registration diagnostic when the expert backend is missing and re-registration.

Pivoted Cholesky connection (#265) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 8 symbols of PSTRF/PSTF2 were connected for the four types and both integer ABIs. The adapter controls the largest-diagonal pivot and stopping by TOL, and composes the native LLT of each pivot with the Schur complement update by native GEMM. Because the public one-shot pivoted LLT uses a fixed internal tolerance, this configuration handles arbitrary TOL and TOL=0.

TOL<0 uses N_DLAMCH(E)_largest diagonal, and candidates after taking the first positive pivot are compared with TOL. RANK<n gives INFO=1, and empty input gives RANK=0/INFO=0. PIV returns the original row numbers at each position after permutation as 1-based values. If the initial diagonal is non-positive, it is not factorized and RANK=0/INFO=1 is set. If computation stops midway, the completed factor, the not-yet-computed permuted triangular part, and the stopping diagonal are returned. With UPLO=U, the internal lower-triangular factor is output conjugate-transposed. The opposite triangle and padding are left unchanged, and the imaginary part of a complex diagonal is not read on input either.

PSTRF/PSTF2 use a common sequential pivot path and allocate an internal dense matrix and native scratch. They do not depend on the contents of the caller's WORK. These LAPACK entry points have no workspace query. Because pivots and rank can change through rounding near the tolerance, the algebraic rank and the numerical rank of the floating-point Gram matrix are distinguished.

test/pivoted_cholesky.jl verifies direct signatures for the four types, both ABIs, and UPLO; PIV and rank; PSD/full-rank/strictly rank-deficient/zero and negative diagonals; reconstruction of partial factors; comparison with OpenBLAS factors and stopping states; the equality boundary of TOL and the automatic tolerance; TOL=0 over a large dynamic range; empty/1×1; padding and unreferenced triangles; the imaginary part of a complex diagonal; integer guards; invalid arguments; the ordinary Julia API; and LBT registration.

Bunch–Kaufman connection (#266) ​

With Julia 1.13.3 / x86_64-apple-darwin and the same pinned colmat-rs revision, the 32 symbols of TRF/TF2, TRS/TRS2, TRI/TRI2/TRI2X, and SV for real SY / complex Hermitian HE were connected to both integer ABIs. Complex symmetric SY systems remain on the existing backend. It uses the partial pivoting of native cholesky::lblt and the separated diagonal, subdiagonal, and final permutation, and converts to LAPACK's classic IPIV and to the storage format of A that includes the intermediate permutations. It undoes the subsequent row swaps of native L to preserve the columns, and also converts back from external LAPACK A/IPIV to call the native solve/inverse. UPLO=U is processed in a basis with reversed row and column order.

TRF uses the native default panel and TF2 the native unblocked path. TRS/TRS2 use a common solve, and TRI/TRI2/TRI2X a common inverse. Matrices and native scratch are allocated internally. The TRF/SV query returns 1, and the TRI2 query on the common inverse path returns max(1,N). The NB of TRI2X is accepted as a blocking hint and uses the same inverse. The opposite triangle, padding, and the imaginary part of a complex diagonal are not read on input. On output too, only the specified triangle is updated.

A 1×1 zero D in factorization/inverse returns a positive INFO at the LAPACK position, and SV does not execute a solve in that case. A non-singular 2×2 block with a zero diagonal is not mistakenly judged singular. The format of the input factor and INFO follow LAPACK, and the native final permutation is not simply returned as IPIV.

test/bunch_kaufman.jl verifies the four types, both ABIs, and UPLO; 1×1/2×2; the 80×80 panel path; reconstruction of PAP' and LDL'/UDU'; solve/inverse residuals; bidirectional interoperation of A/IPIV between native and OpenBLAS; each inverse and driver; singular INFO and preservation of B; query; minimal WORK; insufficient workspace; invalid arguments; padding, integer guards, and unreferenced regions; minimal/maximal scales; the ordinary Julia API; and LBT registration of the 32 symbols. It also regression-checks that complex symmetric problems are not misrouted to HE.

GEBAL/GEBAK connection (#267) ​

The 8 Fortran symbols of GEBAL/GEBAK for the four types were connected to LP64/ILP64. GEBAL uses native balance_in_place_with and GEBAK uses balance_eigenvectors_in_place. JOB=N/P/S/B and SIDE=L/R are handled, and the final permutation is converted to LAPACK's ILO/IHI/SCALE swap encoding. Even when all eigenvalues are isolated, a one-element active range is returned for a non-empty matrix, as in LAPACK. This encoding and range handling are shared with the existing GEEVX.

GEBAK reads and writes only the rows it updates, and does not read SCALE entries unused by the selected JOB, unreferenced rows, or leading-dimension padding. Internally it allocates matrices, permutations, scales, and native scratch, and does not renormalize the eigenvectors.

Tridiagonal EVD driver connection (#268) ​

The four types of STEQR/STEDC/PTEQR/STEGR/STEMR and the two real types of STERF/STEV/STEVD/STEVR/STEVX, 30 Fortran symbols in total, were connected to LP64/ILP64. The normal path calls native tridiagonal_self_adjoint_evd. STEQR and STERF choose the QR path, and STEDC/STEVD switch between QR and divide-and-conquer at the native default threshold of 128. COMPZ=V post-multiplies the existing Z by the eigenvectors. PTEQR forms a bidiagonal Cholesky factor of the positive definite tridiagonal and uses the QR path of native bidiagonal_svd to preserve the relative accuracy of small positive eigenvalues. PTEQR returns eigenvalues in descending order, and the other drivers in ascending order.

The normal path of the range-selection drivers selects A/I/V from the full spectrum. This does not mean that dedicated MRRR or bisection/inverse iteration implementations are provided. The blocked/unblocked names use a common unblocked composition path, and identity with a dedicated native QL/RQ API or the reference implementation's blocked algorithm or performance is not claimed. Working arrays are owned internally.

Triangular-pentagonal QR/LQ and Q application ​

The 28 Fortran symbols TPQRT/TPQRT2, TPLQT/TPLQT2, TPMQRT/TPMLQT, and TPRFB are connected for the four types and LP64/ILP64. Each ABI has 1186 symbols (BLAS 202, LAPACK 984). They compose QR stacking the upper triangle and pentagonal tail, LQ using its adjoint, and generation/application of compact Householder. This does not mean a dedicated native triangular-pentagonal API or the same blocking performance as the reference implementation. Internal matrices and scratch are allocated separately, and the caller WORK is preserved.

TPRFB supports left/right, normal/adjoint, forward/backward, and column/row storage. It does not read or write unspecified triangles, structural zeros, or leading-dimension padding. This series has no LWORK/workspace query, and TPQRT2/TPLQT2 also have no WORK argument. TPRFB has no INFO and reports invalid arguments through the backend's diagnostic code.

Moving and selecting generalized Schur blocks ​

Issue #307 connects the 16 Fortran symbols of TGEXC/TGEX2/TGSEN/GGESX for the four types and LP64/ILP64. Each ABI has 1202 symbols (BLAS 202, LAPACK 1000). The native revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

TGEXC/TGEX2 and TGSEN IJOB=0 use the public generalized Schur reorder. Selecting either member of a real conjugate pair moves the whole 2×2 block, and even when a swap is rejected the factors and positions after the last accepted transformation are preserved. The homogeneous α/β of TGSEN are extracted from the stored factors with the public schur_eigenvalues_real and are not re-decomposed. Infinite eigenvalues with β=0 are preserved, and the normalization of the reference routines is distinguished from the early exit of the complex routines. If eigenvalue extraction is rejected, the unmodified original factors are passed to the saved LAPACK.

GGESX SENSE=N uses the existing native dense QZ/selection path. The condition and separation estimation of TGSEN IJOB=1:5 and GGESX SENSE=E/V/B is delegated to the ILP64 LAPACK from before registration. This does not claim that native provides the same estimates. LP64 converts SELECT and integer workspace and preserves unused output areas. The selection callback of GGESX is also converted to 64-bit LOGICAL, so that callbacks of different calls do not mix through thread-local state and restoration from nesting. Because internal matrices and scratch are owned, this does not imply allocation-free processing or the same operation count and performance as a dedicated native expert driver.

Band/packed generalized self-adjoint EVD and standard-form reduction ​

Issue #308 connects the 32 Fortran symbols GST/GV/GVD/GVX of SBG/HBG/SPG/HPG for the four types and LP64/ILP64. Each ABI has 1234 symbols (BLAS 202, LAPACK 1032). The native revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

packed GST takes an existing triangular Cholesky factor and performs the congruence transformation for ITYPE=1/2/3. band GST restores the split factor S = [U 0; M L] of PBSTF and composes C=XᴴAX and XᴴBX=I from native block triangular solve and reflector transformations. It stores within the original KA bandwidth and does not modify BB, unspecified storage, or padding. It is a composition path using dense owned matrices and scratch, and does not claim the same operation count or performance as a dedicated band bulge chase.

GV/GVD share Cholesky, standard-form reduction, native full EVD, and inverse transformation. The band BB output is a split factor rather than an ordinary triangular Cholesky. A non-positive definite B in band returns INFO=N+i and preserves the partial factor including reverse-order pivots. Unprocessed complex diagonals are not read or written, and only processed/updated diagonals are returned to real values. GVD preserves query and each entry point's minimal WORK/RWORK/IWORK, but it allocates internal areas separately and does not mean execution of the divide-and-conquer algorithm of the same name.

GVX selects A/I/V from the native full spectrum. The Q of band is the full generalized eigenbasis, giving QᴴAQ=diag(λ) and QᴴBQ=I, and the selected columns are returned in Z. Because the diagonal form is also tridiagonal, AB stores the corresponding diagonal tridiagonal matrix. This is not a dedicated partial-eigenvalue or Sturm count algorithm. A positive ABSTOL, native rejection, and range endpoints within the accuracy-based guard are passed to the original ILP64 LAPACK saved before modifying the input. LP64 integer work arrays and IFAIL restore only the slots that were written. Entries of W/Z/IFAIL outside the selection, Q/Z with JOBZ=N, and matrix padding are preserved. It also distinguishes the PEVX behavior of packed N=1 and empty value ranges returning Z=1 and preserving IFAIL. Some versions of the reference implementation of complex HPGVX return with M unset when N=0, but the adapter returns M=0.

Residuals for a positive ABSTOL are judged including the requested absolute accuracy, and the fixed tolerance for the default precision and a strict positive ABSTOL is not relaxed.

band/packed tridiagonalization and packed Q (Issue #309) ​

The 16 Fortran symbols of SBTRD/HBTRD/SPTRD/HPTRD and OPGTR/UPGTR/OPMTR/UPMTR are connected for the four types and LP64/ILP64. Each ABI has 1250 symbols (BLAS 202, LAPACK 1048). The native revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

SPTRD/HPTRD expand only the selected triangle into an owned matrix and convert the real beta gauge of the existing native reduction back to LAPACK's packed AP/TAU format. The imaginary part of a complex diagonal is not read. Generation and application of Q share the existing native Householder application and gather the packed tail directly. The implicit 1, the diagonal, tridiagonal components, and the tails of zero-coefficient reflectors are not read. AP/TAU can also be used mutually with factors generated by reference LAPACK, and OPMTR/UPMTR support left/right application and transpose/conjugate transpose.

SBTRD/HBTRD also expand into an owned matrix and use the same reduction, returning D/E and the band diagonal and adjacent diagonals. VECT=V returns Q, VECT=U returns X*Q for the caller's X, and VECT=N does not reference Q. Complex E reflects the column phase into Q and returns non-negative real values. The real path with KD=0/1 preserves the original tridiagonal form and the identity Q. It does not claim the same operation count or performance as a dedicated band bulge chase, and the owned matrix area is O(n²).

Left and right eigenvectors from Schur form (Issue #311) ​

The 8 Fortran symbols of TREVC/TREVC3 are connected for the four types and LP64/ILP64. Each ABI has 1258 symbols (BLAS 202, LAPACK 1056), and the native revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

The right side uses the public eigenvectors_from_schur_real/cplx. For the left side, the inverted transpose/adjoint of the Schur form is passed to the same helper as an upper-triangular form, and rows and columns are restored to the original order. For real 2x2 blocks, the order of the column pair corresponding to the positive imaginary part and the conjugation on the left side are made explicit. The Schur form is not recomputed; only the specified triangle of the input T and the real first subdiagonal are read.

SIDE=L/R/B, HOWMNY=A/B/S, standardization of SELECT for real pairs, M/MM, and the back-transform of Q_X and Q_Y are preserved. The largest abs1 component of a single column and the largest |re|+|im| of a real pair are normalized to 1. VL/VR outside the specification, columns outside the selection, and T and padding are not modified. SELECT rewrites only real pairs with HOWMNY=S, and complex SELECT is input-only.

TREVC3 shares the same native helper and matrix products and does not mean that Netlib's own blocked back-substitution algorithm is implemented. The fixed WORK and minimal legal LWORK/LRWORK, collective query, and the different check order for real and complex are preserved. Query returns a minimal area sufficient for this path, and there is no guarantee that it matches the recommended value based on the block size of reference LAPACK. Owned matrices and native scratch are O(n²). On native rejection, the input is passed to the saved original ILP64 TREVC/TREVC3 before modifying VL/VR, and LP64 SELECT/M/INFO are converted in a dedicated integer area.

Reordering of ordinary Schur blocks and condition estimation (Issue #312) ​

The 14 Fortran symbols of TREXC/LAEXC/TRSEN/GEESX are connected to LP64/ILP64. TREXC/TRSEN/GEESX handle the four types and LAEXC the two real types. Each ABI has 1272 symbols (BLAS 202, LAPACK 1070), and the native revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

TREXC/LAEXC use the public native checked Schur move and preserve 1x1/2x2 block exchange, accumulation of the transformation into the existing Q, the leading-row adjustment of real IFST/ILST, and the final position. The IFST/ILST of complex TREXC are preserved as input-only. A rejected exchange is undone, and T/Q up to the last successful exchange and the current position are returned. LAEXC does not reference data when N or the block width is zero. Internally it allocates an owned Schur matrix and the necessary Q.

TRSEN JOB=N does not modify SELECT, selects real conjugate pairs together stably, and returns M and the eigenvalues and the necessary Q. For the imaginary part, the square roots of the off-diagonals are computed separately so that a small imaginary part next to a large real part is not lost through relative scaling. Only LWORK=-1 is a query, and LIWORK=-1 alone is an insufficient argument in the real version. The minimal WORK for real JOB=N is max(1,N), for complex JOB=N it is 1, and real IWORK is 1.

GEESX SENSE=N uses the same numerical path as the existing native GEES. The common GEES processing was also fixed so that SDIM on a rejected swap returns the total number of selected columns rather than the moved prefix. SORT=N and query do not call SELECT. Real GEESX treats either LWORK or LIWORK being -1 as a collective query, and the complex version treats only LWORK=-1 as a query. The query on the native path returns a minimal WORK sufficient for that path and is not necessarily the recommended value based on the block size of the reference implementation.

Because there is no public native numerical API for S/SEP and RCONDE/RCONDV, TRSEN JOB=E/V/B and GEESX SENSE=E/V/B use the saved original ILP64 routines. On LP64, SELECT, M, SDIM, INFO, and the integer and logical work arrays are converted, and IWORK/BWORK restore only the slots that were written. The LOGICAL return value of the SELECT callback is converted through a thread-local guard, and the outer callback is restored after a nested call. The invalid-argument INFO of the original routine is also recorded in the adapter diagnostics, and a positive numerical rejection is not treated as an invalid argument.

Generalized QR and equality-constrained drivers (Issue #314) ​

All 16 Fortran symbols of GGQRF/GGRQF/GGLSE/GGGLM are connected for the four real and complex types and both LP64/ILP64. The dependency revision remains 4e6ed0e34659147a5c744ab6431f150e78db6f82.

GGQRF composes A=Q R, B=Q T Z and GGRQF A=R Q, B=Z T Q from the existing native-backed QR/RQ and Q application. The returned reflectors can also generate Q from the original LAPACK ORG/UNGQR/RQ, and both matrices of rectangular/empty/zero/rank-1 input can be reconstructed. For complex Q application, the adjoint rather than the transpose is used. Triangular solve uses the public native solve, avoiding the path where direct division of a complex scalar squares the denominator and makes extreme values NaN.

GGLSE solves min ||c-Ax||₂, Bx=d and GGGLM solves min ||y||₂, Ax+By=d. They check the dimension constraints 0≤P≤N≤M+P and 0≤M≤N≤M+P respectively. If the triangular factor of the first constraint system is exactly singular, INFO=1; if the triangular factor of the remaining free variables is exactly singular, INFO=2. This is not a numerical rank estimate using a rank-revealing tolerance. On failure, the factorization and right-hand-side transformations already performed are preserved, and solutions not yet obtained are not returned as success values. The residual and intermediate-solution payloads of C/D are also updated destructively.

LWORK=-1 is a query and does not modify the input matrices, right-hand sides, solutions, or TAU. The minimal WORK is max(1,N,M,P) for GGQRF/GGRQF, and normally M+N+P for GGLSE/GGGLM, or 1 if N of the system being solved is 0. Query returns the adapter's legal minimum and does not require agreement with the recommended value based on Netlib's block size. Auxiliary matrices, coefficients, and native scratch are allocated separately within the adapter. This does not mean providing a dedicated colmat-rs driver or the same algorithm and performance as Netlib.

In addition to comparing solutions against the original OpenBLAS driver as an independent reference, it checks constraint residuals, stationarity in the free directions, the minimum-norm property, reconstruction with external Q, the boundaries of WORK/INFO/TAU and padding, query, argument order, and exact rank failure. This includes checks that actually obtain the LBT provider and function pointers and call each of the 16 entry points on both ABIs. The driver update order of the implementation follows Reference LAPACK v3.12.1 SRC/dgglse.f / SRC/dggglm.f, and the source and BSD-3-Clause license are recorded in deps/rust/src/constrained_least_squares.rs and deps/rust/licenses/.

GEEVX expert mode and capability verification (Issue #316) ​

The native path of SENSE=N is preserved, and SENSE=E/V/B is delegated to the saved original implementation. If an LP64 original implementation exists, it is called as is; otherwise the saved ILP64 implementation is used. It extends N/LDA/LDVL/LDVR/LWORK and returns ILO/IHI/INFO and real IWORK with checks. For a query, an unreferenced IWORK slot, or an output not written by the original implementation, the caller's value is preserved. Complex RWORK is passed as scratch of the same real type. The internal TREVC3 query may update RWORK.

load_backend() checks the original ILP64 GEEVX for the four types before changing LBT, and returns a configuration error if it is missing. Even in an ordinary Julia environment without an existing LP64 implementation, a legal expert mode is available through the ILP64 implementation. SENSE='?' and combinations with E/B that do not request both left and right eigenvectors are treated as an invalid argument 4. Re-registration does not save Colmat's own GEEVX as the fallback.

When using the low-level DLL directly, the original implementation must be registered before an expert call. colmat_lapack_has_expert_fallback(id,bits) accepts id=0/1/2/3 (s/d/c/z) and bits=32/64, returning 1 if available. On LP64 the saved ILP64 path is also included in availability. If a legal expert call is made while unconfigured, INFO and the computed outputs are left unchanged and configuration diagnostic -1 is recorded in colmat_blas_last_error(). If an external integer output is outside the ABI range, the diagnostic is -2. In ordinary Julia, the check at registration prevents this unconfigured state. No proprietary LAPACK INFO value is added, no success value is returned without computing the condition estimate, and no exception unwinds across the C ABI.

It checks the four types and both integer ABIs, normal computation/query, balance, left and right eigenvectors, all SENSE, minimal WORK, invalid argument order, and padding/integer guards. It compares left and right residuals, non-zero normalization, and condition estimates with an independent reference, and checks direct LP64 delegation also with the test-only OpenBLAS32_jll. It confirms, in independent processes, the configuration that handles LP64 with ILP64 only, removal and recovery of the original implementation, and absence before the first registration. The dependency revision of the numerical API is 4e6ed0e34659147a5c744ab6431f150e78db6f82, and the registration count at the time of this #316 verification is 1,288 for each ABI.
