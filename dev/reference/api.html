API ​

Colmat exports no names. Use Base / LinearAlgebra for matrix operations. Call configuration functions with the Colmat. prefix.

FunctionPurpose
Colmat.load_backend(; verbose=false)Re-register the provided BLAS with LBT
Colmat.backend_library()Return the absolute path of the BLAS shared library
Colmat.get_num_threads()Return Colmat's configured execution width
Colmat.set_num_threads(n)Set Colmat's execution width for matrix multiplication

Because load_backend() runs on load, ordinary use does not require explicit registration. See also Backends and fallbacks and Thread settings.

Colmat Module
julia
Colmat

BLAS/LAPACK backend powered by Rust's colmat. Loading the package installs LP64 and ILP64 forwards in libblastrampoline. Use ordinary Julia arrays and LinearAlgebra; unprovided BLAS/LAPACK routines retain their existing backend.

Colmat.load_backend Function
julia
load_backend(; verbose=false)

Install Colmat's LP64 and ILP64 BLAS/LAPACK symbols in libblastrampoline for this process. Existing forwards for unprovided routines are preserved. GEEVX uses saved original backends for expert condition estimates. LP64 calls use integer conversion to the saved ILP64 backend when no original LP64 routine exists; SENSE=N runs in colmat. An ILP64 GEEVX backend must exist before registration. GGEVX runs BALANC=N/SENSE=N in colmat; other modes require a saved ILP64 expert backend, with integer conversion for LP64 callers. Such a backend must be configured before loading Colmat (Julia normally provides OpenBLAS). SYEVR/HEEVR save ILP64 range drivers for positive ABSTOL, native failures and value intervals near rounded native eigenvalues; LP64 integer outputs are converted. Tridiagonal EVD also saves ILP64 LAPACK entries for native nonconvergence and the relative/absolute accuracy modes not provided by the native API. Generalized self-adjoint drivers save ILP64 entries for native failures and positive-ABSTOL range calculations. SYEVX/HEEVX also save ILP64 entries for positive ABSTOL and native failures. Band/packed selected EVD also retains ILP64 expert entries for positive ABSTOL, native failures and value-range endpoints within a precision-based guard of native eigenvalues. Selected and QR-preconditioned SVD save ILP64 entries for native failures and GESVDQ condition estimation; independent Jacobi drivers remain on the existing backend. TGSEN reorder-only and GGESX SENSE=N calls run in colmat, with ILP64 LAPACK entries for condition and separation estimates, with integer conversion for LP64 callers. Ordinary Schur reordering uses native block swaps; TRSEN JOB=N and GEESX SENSE=N run natively, with saved ILP64 entries for other condition estimates. LP64 integer workspaces and LOGICAL SELECT callbacks are converted explicitly. Structured generalized EVD also saves original ILP64 entries for numerical recovery, positive ABSTOL, and precision guards at selected value boundaries. Call again to select Colmat after loading another BLAS provider. Configure the backend before starting concurrent BLAS work.

Colmat.get_num_threads Function
julia
get_num_threads() -> Int

Return the configured number of participants in Colmat matrix multiplication. The initial value is the BLAS width observed when Colmat was loaded. Other fallback libraries have their own configuration.

source
Colmat.set_num_threads Function
julia
set_num_threads(n::Integer)

Set the number of participants in Colmat matrix multiplication. Pools are created lazily per calling OS thread and replaced when the configured count changes. LinearAlgebra.BLAS.set_num_threads(n) configures Colmat and the loaded fallback libraries together.
