Types and integer ABIs ​

Julia element typeBLAS prefix
Float32s
Float64d
ComplexF32c
ComplexF64z

The same shared library provides LP64 (32-bit integers) and ILP64 (64-bit integers). LP64 Fortran symbols are exposed as dgemm_ and ILP64 ones as dgemm_64_, for example. LBT forwards to the entry point matching Julia's integer ABI. The element precision and the width of integer arguments are independent.

The actual symbol names for iamax are isamax_ / idamax_ / icamax_ / izamax_, and complex norms and absolute-value sums are scnrm2_ / dznrm2_ / scasum_ / dzasum_. CBLAS connects the 172 entry points from #271 to LP64 / ILP64 in addition to the six pre-existing dot entry points. It converts row/column-major layouts, Cint enums, complex coefficient pointers, and 0-based size_t indices. This does not mean that every LBT CBLAS extension is provided. CBLAS GEMM3M composes three native real GEMM operations and allocates temporary storage. Intermediate sums can overflow or lose precision; no optimized 3M kernel or speedup is claimed. Fortran GEMM3M remains arithmetic-compatible ordinary native complex GEMM.

In this configuration, LP64 and ILP64 each register 1480 symbols (374 BLAS and 1106 LAPACK) with LBT. To inspect the registration, run:

julia
julia> using Colmat, LinearAlgebra

julia> cfg = BLAS.get_config();

julia> libs = filter(l -> realpath(l.libname) == realpath(Colmat.backend_library()), cfg.loaded_libs);

julia> Set(l.interface for l in libs) == Set([:lp64, :ilp64])
true

julia> all(length(BLAS.lbt_forwarded_funcs(cfg, l)) == 3116 for l in libs)
true

Native boundary ​

The BLAS ABI is a contract in which the caller passes valid pointers, shapes, leading dimensions, strides, and output regions. In addition to the checks in Julia's ordinary wrappers, the compatibility layer validates options, dimensions, leading dimensions, and zero strides in Level 2/3 calls. Level 1 argument conventions differ by routine.

If argument validation finds a problem, the call returns without computing. The native diagnostic function colmat_blas_last_error() reads and clears the last diagnostic recorded for the calling OS thread. Zero means no diagnostic, and a positive value is the number of the invalid argument. For low-level GEEVX calls, it records -1 if a required original implementation is not configured, and -2 if an integer output of an external implementation is outside the caller ABI's range. These are not LAPACK INFO values. This is not an API that converts Rust exceptions into Julia exceptions or checks the safety of arbitrary raw pointers.

The real SY families and the complex HE families count as the same family per type. GEEVX condition estimation is delegated to the saved original backend, converting integers to ILP64 if no original LP64 implementation exists. An original ILP64 GEEVX for all four types is required before registration. The native support is SENSE=N. For GGEVX, BALANC=N/SENSE=N is native, and other modes are delegated to the existing ILP64 backend. Connection candidates, missing public APIs, and contract differences for all LBT symbols are listed in Full LBT and colmat-rs routine mapping.

ROOK factor connections (#372) ​

The 20 symbols for the real SY / complex Hermitian HE TRF_ROOK, TF2_ROOK, TRS_ROOK, TRI_ROOK, and SV_ROOK routines are connected to both integer ABIs. They use public native Rook pivoting and conversion of the compact IPIV with two swap indices, and verify mutual solve/inverse use with external LAPACK factors. The minimum caller WORK and the query result for TRF/SV are 1, and internal scratch is allocated separately. Subnormal rows receive a symmetric congruence scaling, and subnormal D and right-hand sides receive a per-block common scaling. These also apply to the shared ordinary and packed BK adapters. This does not imply dedicated Fortran algorithms, identical pivot columns, or equivalent performance.
