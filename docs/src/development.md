# Development

## Layout

- `src/Colmat.jl`: the module and load-time initialization.
- `src/backend.jl`: LBT registration, library location, and thread settings.
- `deps/rust/src/abi.rs`: LP64 / ILP64 Fortran BLAS and CBLAS dot entry points.
- `deps/rust/src/kernels.rs`: array borrowing and Rust computation.
- `deps/rust/src/threading.rs`: per-OS-thread pools and thread settings.
- `deps/upstream.toml` / `deps/rust/Cargo.lock`: pins for the source and dependencies.

## Verification

```sh
cargo fmt --manifest-path deps/rust/Cargo.toml --check
cargo test --manifest-path deps/rust/Cargo.toml --locked
cargo clippy --manifest-path deps/rust/Cargo.toml --locked --no-deps -- -D warnings
julia --project -e 'using Pkg; Pkg.build("Colmat"); Pkg.test()'
```

The tests check both LP64 and ILP64 forwarding targets, reference computations with
scalar loops, transposes and complex conjugation, padding, negative strides, zero
coefficients, empty arrays, triangular operations, thread settings, and LAPACK fallbacks.
The standard Julia BLAS tests also run with the same process-wide forwarding configuration.

The old ledger and reproducers have been removed from the current documentation.
[The 0.2 redesign](@ref) explains how to consult the Git history.

## Updating upstream

Check out `deps/colmat-rs` at the desired commit and update the revision in
`deps/upstream.toml` to the same value. Update `Cargo.lock` if needed, then build and test.
Do not mix package-side fixes into the dependency checkout.

After rewriting the shared library, verify with a new Julia process.


## Adding a BLAS symbol

Provide matching LP64 and ILP64 entry points in `abi.rs` and connect them to the
computation in `kernels.rs`. Follow the routine-specific conventions for complex
coefficients and return values, negative strides, zero coefficients, and conditions
under which unreferenced triangular parts or the unit diagonal must not be read.

Borrow Julia arrays only for the duration of the call; do not transfer ownership to Rust
or keep pointers until the next call. Verify the forwarding target and the results through
both LBT and the native ABI, and update [BLAS coverage](@ref) at the same time.

## Verifying the documentation

```sh
julia --project=docs -e 'using Pkg; Pkg.instantiate(; workspace=true)'
julia --project=docs docs/make.jl
```

The documentation build checks for missing public API entries and runs the doctests.
The doctest for the supported-symbol count cross-checks the documentation against the
actual LBT registrations.
The public examples can also be run with `examples/poc.jl`.


## Updating the measured mapping

[Measured Julia API mapping](@ref) is generated by executing ordinary arrays and
cross-checking the LBT forwarding targets.

```sh
julia --project=test test/support_matrix.jl --output=docs/src/reference/support-matrix.md
```

Run `Pkg.build("Colmat")` before generating it, and use a new Julia process.
The probe is also part of `Pkg.test()`, but the ordinary test run does not overwrite the
documentation. The generated version is a snapshot recording the verified Julia version,
platform, and source commit. Keep separate what the Rust side provides, what is callable
from Julia, and what Colmat handles.


## Auditing all LBT symbols

```sh
python3 docs/generate_lbt_inventory.py
julia --project=test test/lbt_inventory.jl
```

Python 3.11 or later is needed only to regenerate this audit, not for ordinary builds or
loads. `docs/lbt-capabilities.json` manages the evidence and restrictions for the public
API, and all canonical LBT names are emitted to a TSV. Unclassified helper functions are
also recorded in the list of routines without an independent public API rather than omitted.
`test/lbt_inventory.jl` checks that the recorded set matches the actual LBT symbol set and
that there are no duplicates.

`deps/generate_symmetric.py` generates concrete C signatures for each precision and
integer ABI of the self-adjoint EVD into `lapack_symmetric.rs`. After changing it, run
Rustfmt on the generated output.
